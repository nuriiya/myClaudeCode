# 项目需求架构文档

## 一、项目概述
- **项目名称**：AI Agent 协作聊天应用（暂定名）
- **项目类型**：Web 网站（浏览器访问）
- **一句话说明**：一个面向个人开发者的 AI 聊天工作台，主控 Agent 能够解析用户意图，按需调用提问 Agent 或生产 Agent，完成需求澄清与代码生成任务。

## 二、目标用户与使用场景
- **目标用户**：个人开发者 / 极客自用
- **使用场景**：
  - 日常开发辅助：快速生成代码、脚手架或小型工具
  - 需求澄清：通过多轮问答逐步明确模糊需求
  - 自动化工作流：将需求澄清与代码生成串成顺序执行链路

## 三、核心功能需求
| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F1 | 主控 Agent（对话 Agent）解析用户意图 | P0 | 识别用户输入是普通对话、需求澄清请求还是代码生成请求，并调度对应 Agent |
| F2 | 提问 Agent 多轮问答补全需求 | P0 | 对模糊需求进行分步提问，最终输出标准化需求文档 |
| F3 | 生产 Agent 后台生成代码 | P0 | 根据明确需求在 workfolder 中生成代码，不单独展示页面，仅在聊天中简要告知结果 |
| F4 | 聊天主界面 | P0 | 支持发送消息、查看对话流、展示 Agent 回复 |
| F5 | 历史会话列表 | P0 | 展示历史对话，支持删除对话 |
| F6 | 设置页 | P0 | 配置 Deepseek token、主题（亮/暗/科技感）、管理 Agent 定义（查看/编辑 md 文件） |
| F7 | 工作目录（workfolder）管理 | P1 | 生产 Agent 生成代码到指定目录，聊天中简要告知生成路径与结果 |
| F8 | 科技感视觉与动效 | P1 | 界面采用渐变、动效等科技感设计 |

## 四、页面/模块结构
- **前端页面共三块**：
  1. **聊天主界面**：核心交互区，展示消息列表、输入框、Agent 状态提示
  2. **历史会话列表**：侧边栏或独立页，支持查看和删除历史会话
  3. **设置页**：包含 token 配置、主题切换、Agent 定义 md 文件查看/编辑
- **生产代码/workfolder 前端展示**：不单独做展示页，仅在聊天中简要告知生成结果（如“已生成到 workfolder/xxx”）

## 五、技术要求
- **后端**：Node.js
- **前端**：React
- **数据库**：SQLite（存储对话历史、配置信息）
- **敏感配置**：Deepseek token 使用环境变量管理
- **运行环境**：浏览器访问的 Web 网站，本地或服务器部署均可
- **代码输出**：生成文件到指定 workfolder 目录

## 六、数据与存储设计
- **对话记录**：SQLite 存储，包含会话 ID、消息内容、角色（用户/主控/提问/生产）、时间戳
- **应用配置**：SQLite 存储（主题、Agent 定义路径、workfolder 路径等）
- **Token**：环境变量 `DEEPSEEK_TOKEN` 管理，不落库
- **Agent 定义**：Markdown 文件存储，设置页可查看；文件路径记录在配置中

## 七、视觉与交互要求
- **整体风格**：科技感
- **核心元素**：渐变背景、动效过渡、发光边框或粒子效果
- **模式**：支持暗色模式优先，可切换主题
- **交互**：聊天流顺畅，Agent 切换时有状态提示，动效不干扰操作

## 八、交付边界
- **本期实现**：上述 P0 与 P1 功能全部实现
- **暂不实现项**：无（用户明确“全部实现”）
- **生产代码前端展示**：本期不做独立展示页，仅聊天中简要告知

## 九、验收标准
- **主流程可用**：用户发送需求 → 主控 Agent 识别意图 → 正确调用提问 Agent 或生产 Agent → 返回结果
- **提问链路**：提问 Agent 能进行多轮问答，最终生成需求文档
- **生产链路**：生产 Agent 能在 workfolder 生成代码，聊天中给出简要告知
- **基础功能**：聊天界面可正常收发消息；历史会话可查看、删除；设置页可配置 token、切换主题、查看 Agent 定义
- **视觉达标**：界面具备渐变与动效，视觉风格符合科技感预期
- **稳定运行**：核心功能无阻塞性 bug，可完成一轮完整的需求澄清+代码生成流程
